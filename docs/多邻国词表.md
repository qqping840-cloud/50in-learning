# 多邻国词表（单词页的第二个来源）

把你在多邻国学过的词拉进本项目，点一下就能听多邻国原声，汉字形按「常用才补、拿不准不补」的规则自动处理。

- 前端：`js/duo.js`（界面）+ `css/duo.css`
- 服务端：`duo-sync.js`（同步、下载发音、补汉字形）
- 触发：单词页顶部切到「多邻国」→ 点「更新」→ `POST /api/duo/sync`
- 产物：`assets/data/duolingo-words.json`（个人词表，**不进 Git**）、`assets/audio/duo/*.mp3`（原声，**不进 Git**）

## 一、首次配置

`config.json`（私人文件，不进 Git）里要有三项：

```json
{
  "duoToken": "Bearer eyJhbGciOiJ...",
  "duoUserId": "1621482876",
  "duoCourse": { "learning": "ja", "from": "zh" }
}
```

| 字段 | 怎么拿 |
|---|---|
| `duoUserId` | 打开自己的多邻国主页，URL 里的那串数字 |
| `duoToken` | 浏览器登录多邻国 → F12 → Network → 任意 `www.duolingo.com` 请求 → 复制 `Authorization` 头（整串，含 `Bearer `） |
| `duoCourse` | 学什么语言写 `learning`，从什么语言学写 `from`；中文界面的日语课是 `ja` / `zh` |

`duoToken` 是个长效 JWT（本项目实测的这枚 `exp` 到 2170 年）。**哪天报「多邻国拒绝访问」，就是它失效了，重取一次填回来即可，不用改代码。**

> 注意：这里存的是你自己的登录凭证。`config.json` 已进 `.gitignore`，别把它贴进 issue、聊天或截图。

## 二、同步做了什么

```
① 读进度   GET  /2023-05-23/users/{id}?fields=currentCourse
              └ 从 currentCourse.skills 里取每个单元的 finishedLevels / finishedLessons
② 拉词表   POST /2017-06-30/users/{id}/courses/{学习语}/{母语}/learned-lexemes
              └ Body: { progressedSkills: [{finishedLevels, finishedSessions, skillId:{id}}], startIndex }
              └ 有 pagination.nextStartIndex 就继续翻页
③ 下发音   逐个下载 audioURL → assets/audio/duo/<sha1(词)>.mp3
④ 补汉字形 见第四节
⑤ 落盘     assets/data/duolingo-words.json
```

**「已学」的判定口径**：`finishedLevels > 0 || finishedLessons > 0` 的单元算学过；
上报给多邻国的 `finishedSessions` 用 `finishedLessons`（这个组合实测与网页上显示的词数完全一致，2026-10 时为 159 个词）。

接口是逆向出来的，**不是官方公开 API**：多邻国改版就可能失效。失效时页面会显示原因，`logs/app.jsonl` 里记 `duo_sync_failed`。

**只读不写**：整个流程只调用读取类接口，不会回写账号数据。

## 三、发音

- 来源是**多邻国自己录的原声**，不是 Edge 合成音（项目里其他发音走 `UI.speak` → Nanami，这里是唯一例外，走 `UI.speakUrl`，共用停止逻辑，不会叠音）
- 文件按**词**缓存：`assets/audio/duo/<sha1(词)>.mp3`
- 每轮同步会把远端音频地址存进 JSON（字段 `src`）。**同一个词如果多邻国换了录音（地址变了），下次同步会重下覆盖**——早期版本只按词名缓存，永远不刷新，已修
- 已经不在词表里的旧文件不会自动删（几百 KB，删了反而要重下）

## 四、汉字形的规则

多邻国只给假名和中文释义，汉字教学本来就是它的弱项，所以在同步时补一次（`duo-sync.js` 的 `resolveKanji`）。

| 情况 | 处理 | 例 |
|---|---|---|
| 已经是汉字形 | 跳过 | `新しい`、`四時` |
| N5 词表里有，且中文释义对得上 | 用词表里的 | `えん（日元）→ 円`，不会套成「園」 |
| N5 里有但对不上 | 当作没有，继续往下判断 | `とし（城市）` 不会被套成「年」 |
| JMdict 唯一常用候选 | 用 | `まんが → 漫画`、`やきゅう → 野球` |
| JMdict 多个候选 | **不猜，留空** | `はし`（橋/箸/端） |
| 助词 / 代词 / 叹词 / 单假名 | 跳过 | `は`、`ね`、`さん` |
| 指示词、寒暄语 | 跳过（现代日语只写假名） | `ここ`、`こんにちは`、`はじめまして` |
| `ます` 形 | 查辞书形再还原 | `たべます → 食べます` |

判据文件：`assets/data/kana-kanji.json`（JMdict 常用子集派生的「假名 → 汉字」映射，446 KB，离线查，不联网）。
需要重建时用 `python tools/build_kana_kanji.py <jmdict-eng-common.json>`，来源与许可见 `THIRD_PARTY.md`。

**改规则后必须跑自检**：

```powershell
node tools/test_duo_kanji.js
```

自检里的 13 条断言覆盖的就是上表每一条（含「该不补」的反例），别只测正例。

## 五、界面

| 交互 | 行为 |
|---|---|
| 点整行 | 播放该词原声，播放中那行高亮 |
| 搜索框 | 假名 / 汉字 / 中文都能搜，边打边筛 |
| 「标记」 | 标记已会，行会变淡；状态存 localStorage `duo-done`，重跑同步不丢 |
| 「更新」 | 触发同步，完成后提示「N 个词、补汉字形 N 个、新下载 N 条」 |
| 顶部切换 | 记住上次选的是 N5 还是多邻国（localStorage `vocab-source`） |

## 六、排错

| 现象 | 原因 / 处理 |
|---|---|
| 提示「还没配置多邻国账号」 | `config.json` 缺 `duoToken` 或 `duoUserId` |
| 提示「多邻国拒绝访问（token 过期或不对）」 | 重取 Authorization 头填回 `duoToken` |
| 提示「多邻国返回 0 个词」 | 账号确实没学，或 `duoCourse` 配错了课程 |
| 提示「正在同步中」 | 上一个同步还没跑完，等它结束；服务端有单飞保护 |
| 某个词没声音 | 该词没有 `audioURL`（少数词如此），或下载失败；看 `logs/app.jsonl` 的 `duo_sync` 计数 |
| 汉字形明显不对 | 先跑自检；再确认是不是 N5 词表里的释义导致误配，必要时把该词加进 `duo-sync.js` 的 `KANA_ONLY` 或补测试用例 |
| 页面 404 打不开 | 服务没起，`start.bat` 或 `node server.js` |

## 七、已知限制

- **只同步当前课程**。多邻国账号里别的课程（比如英语）要改 `duoCourse` 再同步一次，会覆盖当前词表（不合并）
- 词表**只增不减**：多邻国的「已学」不会因为不练而消失，所以词数只会涨
- 汉字形在**同步时**算一次；改了规则要再点一次「更新」才生效
- 没有做「只重算汉字形、不动音频」的快捷入口（目前走完整同步，约 20 秒）
- 手机端只做了响应式，没有真机验证
